# 아기 무염 식단 · 텔레그램

매주 수요일 한국시간 저녁 8시에 다음 주 월요일~일요일 아침·점심·저녁 21끼와 통합 장보기 목록을 생성하는 Codex 예약 작업용 발송 도구입니다. 사용자의 최종 수신 방법은 텔레그램입니다. 메일과 카카오톡은 사용하지 않습니다.

## 연결

`node telegram.mjs setup`으로 연결 화면을 열고 `http://127.0.0.1:18743`에 접속합니다. BotFather에서 생성한 봇의 토큰을 입력하고, 화면의 전용 봇 링크를 열어 **시작**을 누른 뒤 **연결 확인**을 누릅니다. 새 봇 사용을 권장합니다. 기존 웹훅이 있는 봇의 설정은 변경하지 않습니다.

토큰은 브라우저 입력으로만 받으며 명령행·대화·로그에 적지 않습니다. 연결 후 토큰과 개인 채팅방 ID는 `.state/telegram.dpapi`에 Windows 현재 사용자 암호화로 저장됩니다. 다른 Windows 계정으로 실행하려면 다시 연결해야 합니다.

## 예약 실행에서 사용할 순서

1. `node telegram.mjs status`로 연결 상태를 확인합니다. 이 명령은 토큰과 채팅방 ID를 출력하지 않습니다.
2. 대상 주의 월요일 날짜를 기준으로 7일치 21끼 식단을 한국어 UTF-8 텍스트로 `menus/weekly/YYYY-MM-DD.txt`에 작성합니다. 사용자 조건과 주간 재료 반복을 반영합니다. 원문을 읽지 않은 창작 레시피를 공공기관 공식 레시피라고 표시하지 않습니다.
3. `node telegram.mjs send menus/weekly/YYYY-MM-DD.txt week-YYYY-MM-DD`를 실행합니다. 결과가 `sent`일 때만 발송 완료라고 보고합니다. `already_sent`는 같은 주의 발송 완료 기록이 있다는 뜻입니다.
4. 긴 글은 텔레그램 길이 제한에 맞춰 번호가 붙은 여러 메시지로 같은 실행에서 전송합니다. `.state/receipts.json`에 날짜별 발송 성공과 메시지 ID를 기록합니다.
5. 네트워크 오류로 발송 결과가 불확실하면 중복 발송을 막기 위해 자동 재전송을 중단합니다. 사용자의 실제 수신 여부를 확인한 뒤에만 기록을 조정합니다. 성공 확인 없이 잠금·발송 기록을 지우거나 다른 날짜 키를 써서 재전송하지 않습니다.

이 환경의 기본 샌드박스에서는 Telegram API 접속이 EACCES로 거부되며, Windows 사용자 암호화 저장소를 읽는 실행 계정도 달라집니다. **연결 상태 확인(status), 연결 화면(setup), 실제 발송(send) 모두** `exec_command`의 `sandbox_permissions: require_escalated`로 실행합니다. 기본 샌드박스의 복호화 실패를 실제 연결 해제로 오인하거나 사용자에게 토큰을 다시 요청하지 않습니다. 사용자가 요청한 Telegram 접속과 저장소 접근 범위에서만 사용하고 계정 전체 보안 설정은 바꾸지 않습니다. 자동 승인 검토가 접속을 거부하면 발송 완료로 표시하지 말고 완성된 식단과 정확한 차단 원인을 이 작업에 남깁니다.

작업 폴더: `C:\Users\rhj27\OneDrive\Desktop\Codex file\아기식단_텔레그램`

Node 실행 경로: `C:\Users\rhj27\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe`

정기 실행은 Codex의 현재 작업에 연결된 자동화를 사용합니다. 별도의 Windows 예약 작업은 만들지 않았습니다. 예약 시간에는 이 PC와 Codex 앱이 실행 중이어야 합니다.

컴퓨터가 꺼져 있어도 보내려면 `GITHUB_SETUP.md`의 GitHub Actions 구성을 사용합니다. GitHub 저장소에는 `.state/telegram.dpapi`를 올리지 않으며, 텔레그램 토큰과 채팅방 ID는 GitHub Secrets로만 등록합니다. GitHub Actions 구성에서는 `scripts/generate_weekly.mjs`가 보관된 공개 레시피 색인으로 식단을 만들고 `scripts/cloud_sender.mjs`가 중복을 확인한 뒤 발송합니다.

## 초기 조건

- 2026-09-13 기준 12개월. 사용자는 알레르기 반응을 특별히 관찰하지 못했다고 했으며, 의학적으로 알레르기 없음이 확인된 것은 아닙니다.
- 소금·간장·된장·액젓·가염 육수·설탕·꿀을 추가하지 않습니다. 식재료 자체 나트륨 0을 뜻하지 않습니다.
- 밥은 쌀컵 2컵에 밥솥 2.5컵 눈금으로 짓습니다. 기존 밥을 활용하고 질감은 실제 먹는 능력에 맞춥니다.
- 초기 보유 재료: 쌀, 양파, 대파, 돼지안심, 소고기, 냉동 순살 가자미, 고구마, 우유, 요거트. 양은 미확인입니다.
- 같은 채소를 2~3일 돌려 써 장보기 품목을 줄이고, 주 단위로 식품군과 단백질을 순환합니다. 장봤다고 확인받지 않은 재료를 실제 재고로 단정하지 않습니다.
- 첫 주 예시는 `menus/weekly/2026-09-14.txt`에 있습니다. 2026년 9월 14~20일 식단을 포함하며, 이후 매주 수요일 저녁 8시에 다음 주 월~일 식단을 생성합니다. 기존 `menus/2026-09-14.txt`는 주간 전환 전에 보낸 단일 날짜 발송 기록으로 보존합니다.

## 제철과 원문 확인

- 먹는 날의 한국 기준 월에 맞는 국내 제철 농산물을 우선 선택합니다. 기본 쌀·고기·양파 등 모든 재료를 제철이라고 주장하지 않습니다. 제철 근거는 농촌진흥청·농사로·공공 급식지원센터 등 실제 읽은 자료의 연월·링크로 남깁니다.
- 9월 첫 식단의 고구마·느타리버섯은 아이사랑에 공개된 해남군 급식지원센터 2025년 9월 식단안내 3쪽 ‘9월 제철 식재료’를 확인했습니다: https://info.childcare.go.kr/info/pnis/search/PnisFileDownload.jsp?STCODE=46820000004&flag=DNLL&wkyymm=202509
- 은평구 기본 출처: https://www.eunpyeongcenter.co.kr/sub02/sub01.php . 게시글 대상 연월, 게시일, **원문 식단 날짜**, 정확한 첨부파일명·시트·셀, 원문 메뉴명을 남깁니다. 이번에 먹는 날짜와 출처 메뉴의 배정 날짜는 구분합니다.
- `sources/eunpyeong/index.json`은 게시글·첨부파일·원본 SHA-256 목록, `recipes.ndjson`은 추출된 검색 색인입니다. 원본 XLSX는 변경하지 않았습니다. 색인만 보고 원문 확인을 마쳤다고 표현하지 않습니다.
- 검색 예: `python -X utf8 query_sources.py --month 9 --name 느타리 --limit 5`. 선택한 행을 원본으로 재열람할 때 `--read`를 더합니다. 실제 실행은 README에 적힌 번들 Python 경로를 사용합니다.
- 메뉴를 선택하면 원본 셀의 날짜·요일·분량을 대조하고 게시글의 작성일을 확인합니다. `dateIssues`가 있거나 `sourceDate`가 null인 행은 자동 선택에서 제외합니다. 잘못 적힌 날짜를 추측해 수정하지 않습니다.
- 실제 날짜 오류 예: `4060/2026년 9월 완료기 이유식 레시피.xlsx`의 ‘1주’ A26은 `21 (수)`, ‘2주’ A68은 `18 (토)`로 적혀 달력과 맞지 않습니다. 한글 식단에는 각각 다른 일자로 배열되어 있어 자료 간 불일치도 있습니다. 이 행은 첫 식단에서 제외했습니다.
- 각 식단의 `menus/YYYY-MM-DD.sources.json`에 원문 식별 정보·대조 결과·변경 내용을 기록합니다. 원문에서 소금·소스 제거, 분량·재료·조리법 변경은 모두 ‘가정용 변경’으로 밝힙니다. 오전간식에서 아침 한 끼로 바꾼 경우도 표시합니다.
- 자료 수집·텍스트 추출·개별 메뉴 검증은 서로 다릅니다. 현재 범위와 한계는 `자료확인현황.md`를 확인합니다. 홈페이지 전체 학습이나 의학적 검수를 마쳤다고 주장하지 않습니다. 센터의 과거 식단 안내를 현재 의료 지침으로 그대로 일반화하지 않습니다.

## 자료 도구

- `collect_eunpyeong.mjs`: 공개 식단 게시판 자료 수집. 이미 받은 항목은 건너뛰며 한 번에 한 요청을 수행합니다. HTTP 401/403/429를 받으면 즉시 중단하고 기록을 보존합니다. 제한을 우회하거나 짧은 간격으로 재시도하지 않습니다.
- `extract_sources.py`: 원본 XLSX의 값과 레시피 검색 색인 추출. 날짜·요일 불일치는 표시하고 유효 출처 날짜를 비웁니다. 표의 시각적 배치 검증이나 모든 레시피의 수동 검증을 뜻하지 않습니다.
- `extract_hwp_text.py`: HWP 본문 문자 추출. 잘릴 수 있는 미리보기 텍스트 대신 BodyText 구역을 읽습니다. 표의 병합 관계·그림 속 글자·실제 화면 배치를 복원하지 않으므로 날짜와 메뉴 관계를 단순 텍스트 순서로 자동 확정하지 않습니다. `.tools`의 olefile을 사용하므로 이 환경에서는 `require_escalated`로 실행합니다.
- 번들 Python: `C:\Users\rhj27\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe` (`-X utf8` 사용).
- 자동화 파일은 기본 샌드박스에서 이전 내용이 보일 수 있으므로 저장 확인은 `require_escalated`로 읽습니다. 도구의 성공 응답과 실제 저장된 수신 방법·시간·프롬프트를 대조합니다.
